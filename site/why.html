Why Magpie · the architecture

An MCP server that has no LLM.

Three actors. One Node process. Sandboxed previews. Everything on your disk.

Magpie is a local dashboard plus an embedded MCP server for the visuals your AI agent makes — mockups, diagrams, charts, status reports, plans. The server is dumb infrastructure. No model weights. No inference. No telemetry. Decisions live in a portable skill on the host side; data lives in ~/.magpie/ on your machine.

01Three actors. One nest.

You are the reader they all serve. Magpie is the bird; the Nest is your disk; the Master is the skill your AI gets.

trainer

Master

Teaches your AI Magpie's rules.

A portable Agent Skill bundled in the npm tarball at skill/magpie-master/SKILL.md. Pure judgment — picks projects, decides iterate vs add, asks before filing when uncertain. No code. No storage.

trained bird

Magpie

Tends the nest, version after version.

Your AI coding agent (Cursor, Cline, etc.) with the Master skill loaded. Calls MCP tools to bring visuals to the Nest, arrange them by project, keep versions in order.

dumb infra

Nest

Local. Quiet. Yours.

One SQLite file. One blobs folder. Lives at ~/.magpie/. Holds what your Magpie brings. No LLM. No telemetry. Never phones home.

Master trains·Magpie tends·Nest keeps.

02One process. Two surfaces.

npx magpie-mcp boots a single Node process that listens on two channels: stdio for your AI host, HTTP + WebSocket for your browser. Auto-port discovery if 3737 is taken.

The hot path

  • Your AI writes source (HTML / Mermaid / SVG / Markdown / DOT / Vega-Lite / D2) and calls add_visual or iterate over stdio.
  • Magpie writes the bytes to ~/.magpie/blobs/<id>/v<n>.<ext>, inserts a row in SQLite, kicks the render pool for a PNG thumbnail.
  • WebSocket pushes the new visual to the browser tab. You see it land in the dashboard within a second.
  • Per-host MAGPIE_HOME isolates instances. One canonical process per home; subsequent npx magpie-mcp invocations become facades that multiplex over a named pipe.

03Infra is dumb. That's the point.

The server has no model. The decisions happen on the host side, inside the trained AI. Dumb infrastructure is small, fast, auditable, and impossible to compromise in interesting ways.

no model

Small surface

~200 KB pre-deps. Single Node process. No model weights shipped. No inference happens inside Magpie. The MCP tools are thin wrappers over SQLite and the filesystem.

sync

Fast by default

better-sqlite3 is sync. Sub-millisecond filter and search across thousands of visuals. No ORM. No async overhead. Raw SQL is the convention.

portable

Skill, not service

The decision protocol lives in a portable Agent Skill bundled in the tarball. Any MCP-aware host with skill support gets the same behavior. The server stays the same; the brains travel with the host.

auditable

Read the source

MIT license. ~5K LOC of TypeScript in strict mode. Raw SQL, no ORM. The whole protocol surface fits on one page — 14 tools, 3 resources.

04Sandboxed by architecture.

Magpie renders content your AI wrote. That source might be untrusted. Five concrete defenses keep the dashboard, your data, and the rest of your machine isolated.

  • Iframe sandbox. Every visual renders in an iframe with allow-scripts only — no allow-same-origin. A hostile HTML mockup can't call back to the Magpie API, can't read other visuals, can't touch localStorage. (v0.9.2 A2 lock.)
  • Markdown sanitized. Markdown goes through marked + DOMPurify before rendering. SVG sources are sanitized inline before serving.
  • DNS rebind guard. The HTTP server validates Host headers against the bound interface — protects the dashboard from DNS-rebinding attacks aimed at the localhost API.
  • Read-only ingest. When your AI passes content_path, Magpie reads + copies the bytes into the next blob slot. Magpie never moves, edits, or deletes your source files. Ever.
  • Local bind. Default bind is 127.0.0.1. No exposure to other machines on your network. Override with MAGPIE_BIND only when you mean to.

The full prod-readiness audit (59 probes across 8 dimensions) closed with 0 open findings at v0.9.2 — SECURITY.md covers the threat model.

05Local-only by architecture, not by policy.

There is no cloud option. There is no telemetry switch. The data layout is open and the backup is one folder copy.

~/.magpie/ # or wherever MAGPIE_HOME points ├── magpie.db # SQLite — projects · visuals · versions · tags · templates · outbox ├── magpie.lock # pid + IPC pipe name for the canonical process ├── blobs/ │ └── <id>/ │ ├── v1.html # your AI wrote this │ ├── v1.png # puppeteer-core thumbnail │ ├── v2.html │ └── v2.png └── ipc/ # named pipes for multi-shell facades
  • Backup is a folder copy. Quit Magpie, copy ~/.magpie/, you're done. Or run npx magpie-mcp --backup for a USTAR + gzip archive with a WAL-consistent snapshot.
  • Migrations are forward-only. The runner detects gaps and downgrades at boot. The downgrade path is restore from an older backup — there is no schema rollback by design. (R21.)
  • Restore is an extract. Untar into ~/.magpie/, reboot Magpie. Missing migrations replay on next boot.
  • No accounts. No sync. Single user. Single machine. If you want it on another machine, copy the folder.
